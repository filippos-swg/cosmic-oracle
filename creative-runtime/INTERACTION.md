# ASTRA — INTERACTION.md
Status: Creative Runtime pilot.

## Interaction proposition
The visitor encounters a physical machine, not a website. The rotary telephone dial is part of the meaning of the piece.

## Existing ceremony
BOOT → IDLE → IDENTIFY → CONSULT → READING → IDLE

Treat this sequence as a ceremony, not a funnel.

## Rules
- One clear action at a time.
- Physical input receives unambiguous but restrained acknowledgement.
- Never expose implementation complexity.
- Do not introduce web navigation metaphors.
- Recovery from mistakes should be simple and calm.
- Waiting may contribute to ceremony, but never disguise a broken state.
- The system should remain understandable without explanatory UI clutter.

## Hardware
Primary installation input: rotary dial emulating keyboard digits.
Keyboard parity is useful for testing, not the conceptual model presented to visitors.
4:3 CRT and safe-area constraints are first-class design constraints.

## Accessibility and robustness
Legibility and contrast on the physical display matter more than fashionable subtlety.
Do not encode essential state solely in faint contrast or motion.
Respect reduced-motion considerations where compatible with the installation's authored environmental behaviour.

## Test
Could a first-time visitor operate ASTRA after seeing only the machine and its on-screen invitation? If not, improve the ceremony before adding instructions.
